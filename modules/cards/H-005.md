# H-005 · 헤드리스 하네스 러너

> 섹터 **harness** · 마일스톤 **M0 Harness Bootstrap** · 우선 **P1** · 크기 **M** (≈1.5 세션) · 담당 서브에이전트 **module-builder**

## 1. 목표
`claude -p`로 카드 1장을 끝까지 실행하고 결과를 기록하는 러너. 병렬 시 git worktree 사용.

## 2. 의존
- H-004 — 진행 보드 생성기

## 3. 생성·수정 파일
- `harness/run_card.sh (키트 포함본 검증)`
- `harness/orchestrate.py (키트 포함본 검증)`
- `harness/runs/.gitkeep`

## 4. 공개 인터페이스
```python
harness/run_card.sh C-101                  # 단일 카드
uv run python harness/orchestrate.py --milestone M1 --parallel 2 --dry-run
```

## 5. 구현 단계
- dry-run으로 실행 계획 출력 확인
- S 크기 카드 1장을 실제 실행해 runs/<id>.json 생성 확인
- worktree 병렬 2개 실행 후 머지 절차를 harness/README.md에 기록

## 6. 수용 테스트 (Definition of Done)
- [ ] dry-run이 의존성 순서를 지킨다
- [ ] 실행 후 registry status가 `review`로 바뀐다
- [ ] `uv run pytest -q` 전체 통과 · `uv run ruff check` · `uv run lint-imports` 통과
- [ ] 섹터 `public.py`에 새 공개 이름 반영 (해당 시)
- [ ] `modules/registry.yaml` status → `review`, `state/HANDOFF.md` 갱신

## 7. 읽을 것 (컨텍스트 예산 — 이 목록 밖은 열지 않는다)
- 이 카드
- `AGENTS.md` §코딩 규칙 (CLAUDE.md가 자동 포함)

## 8. 금지
- 다른 섹터의 `public.py` 외 파일 import·열람
- 계약(docs/02_CONTRACTS.md) 변경 — 필요하면 멈추고 ADR 초안만 작성
- 단위 테스트에서 실 LLM·네트워크·Postgres 호출
- 파일 1개 300줄 초과 (넘으면 분할)

## 9. 학습 포인트
H8, H11 → `docs/06_LEARNING_TRACK.md`에서 해당 항목을 읽고, 끝나면 `learning/<패턴ID>.md` 노트 작성

## 10. 메모
처음 3~5장은 **대화형으로** 만든다. 러너는 카드 품질이 검증된 뒤 쓴다.
